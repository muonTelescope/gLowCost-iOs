# How the app got here

The app was built over one long day (26 September 2026, all times ET) in three AI-assisted sessions, plus this repository's clean-up. This page records what each session did and which decisions carried forward, so later changes can be judged against the reasons.

## 1. ChatGPT: "Generate Pressure Corrected Charts" (before the app)

Starting point: SD-card logs from the detector (`muon_….csv` counts per minute, `env_….csv` temperature and pressure) and the question of how much of the rate variation is atmospheric.

- Barometric coefficient fitted on the logs: **β_P ≈ −0.15 % per hPa**, relative to a reference pressure **P₀ = 982.864 hPa**.
- A temperature coefficient **β_T ≈ −0.393 % per °C** around **T₀ = 24.637 °C** came out of the same fit, but was flagged as provisional (short runs, temperature correlated with time of day and with the detector's own SiPM bias compensation).
- These coefficients went into the first iPhone app as "corrected" chart lines next to raw counts (see the v1 screenshot `history/iphone-charts-demo.png`).

**Decision later (Claude session): drop in-app correction entirely.** The detector already compensates the SiPM bias for temperature, the fitted temperature term was not trustworthy, and a correction baked into a phone app is hard to audit. The app now stores and shows **raw counts only**, and records pressure, temperature and GPS with every minute so any correction can be done later, in analysis, with the full data set. There is no correction anywhere in this repository.

## 2. Codex: firmware Wi-Fi window, Bluetooth telemetry, app v1 (about 4:15–6:50 PM)

Codex worked in the firmware repository (`ESP32-P4-gLOWCSOT-cubesat`, fork of the gLOWCOST cubesat detector firmware) on the physical detector connected to a Mac.

- **Diagnosis:** the detector's Wi-Fi access point switched itself off after a few seconds (7 s in the repository, 20 s in the installed image). This was a deliberate firmware timer, not a power fault. See `history/codex/source-findings.md`.
- **Firmware changes:** Wi-Fi window extended to **120 s** after boot (or held on by command), and a **Bluetooth LE** service added: the detector advertises as **MuonP4** in a short window every **15 s**, serves a 160-byte telemetry packet per completed minute (protocol v4, [BLUETOOTH-PROTOCOL.md](BLUETOOTH-PROTOCOL.md)), a JSON command channel for status, HV, DAC, FPGA, clock and SD files, and encrypted pairing for commands. A physics minute only counts when Wi-Fi is off and HV has settled.
- **App v1** (`MuonMonitor`, SwiftUI, iOS 17): live counts, charts with the ChatGPT correction, detector controls. Screenshots in `history/`.
- **Tests:** firmware flashed and exercised over Bluetooth from the Mac (discovery, reads, notifications, bonding across reboot, first physics minute with 60,000 ms exposure). See `history/codex/HARDWARE-TEST.md` and `VERIFICATION.md`.
- **Left open:** one observation where the Wi-Fi SSID did not appear on the Mac or iPhone even though the firmware reported Wi-Fi on. The P4 flag does not prove the ESP32-C6 radio is beaconing. This is why the app has a stubbed **Radio diagnostics** card that waits for a firmware `wifi_status` command.

## 3. Claude: app v2 and the violet & phosphor redesign (about 9:15–11:05 PM)

Claude (cowork session) rewrote the app for iOS 26 and then redesigned its look with the user.

Product decisions (archived in [`../design/ios-redesign-plan.md`](../design/ios-redesign-plan.md)):

- iOS 26+, Tab API with Now / Runs / Detector / Settings, a logging bar on every tab. Friendly by default, **Expert mode** for HV, DAC, FPGA and raw counters.
- **Raw counts only** (see above).
- Runs stored with SwiftData, renameable (renaming the live run also renames the SD files on the detector through the BLE `label` command), default tag groups (Power, Radio, Place, Purpose) plus custom tags, notes and events.
- Per-minute GPS: track coloured by rate, altitude chart, chart scrubbing moves the map marker.
- Added: event markers, counting-statistics health check (detrended Fano factor per pair: clean runs 0.90–1.04, the Sep 23 mains run with Wi-Fi on 1.29 on CH02), local alerts, SD gap fill over Bluetooth and CSV import (old and new firmware formats), compare runs, Siri/App Shortcuts, share card, VoiceOver labels.
- Storage in a folder the user picks once (iCloud Drive › cosmic) through a security-scoped bookmark, so it works with a free Apple account.
- Live Activity with a Stop button, Dynamic Island, Home and Lock Screen widgets, Control Center controls.
- Project generated by a script; `Config.xcconfig` holds team, bundle ID and the optional App Group.

Visual decisions:

- The user picked one direction, **"violet & phosphor"**, and asked for a single version rather than variations: dark violet ground, violet for structure, lilac muon tracks, phosphor green for anything that is data, pink reserved for alerts. Raleway for words, IBM Plex Mono for numbers.
- **Chamfered corners** instead of rounded ones, with a 1 px hairline that follows the cuts. (The first mockup clipped its borders on the diagonals; it was fixed by drawing the edge as a separate layer, which in SwiftUI is one `InsettableShape` used for both clip and stroke.)
- After a first pass without any blur or gradient, the user asked for **frosted glass on floating bars**, sheets and tooltips, and **subtle gradients**: panel sheen, hero fade, primary button.
- Channel notation **CH⁰₁ / CH⁰₂ / CH¹₂** and **ΣCH** for the sum.
- Claude rendered the mockup and reviewed it: [seven fixes](../design/REVIEW-7-FIXES.md) (hero fade, small channel digits, pink restricted to alerts, green bars on Lock Screen and widgets, tooltip placement, wrapping, empty space).

The session could not reach a Swift toolchain, so v2 was delivered as an uncompiled git bundle (`ios-redesign` branch, commit `878f099`) with the redesign still only in the mockup.

## 4. This repository

`muonTelescope/gLowCost-iOs` holds **only the iPhone app** (the firmware stays in its own repository; the telemetry encoder is vendored under `tests/protocol/` for the wire-format test).

- Imported v2 from `ios-redesign` @ `878f099` unchanged (first commit), then:
- Ported the violet & phosphor design into shared tokens (`Palette`, `Typography`, `Chamfer`, `Glyphs`) used by the app and the widget extension, and applied all seven review fixes.
- Bundled Raleway and IBM Plex Mono (SIL OFL 1.1) in both targets.
- Decided defaults, each easy to change:
  - custom chamfered frosted tab bar and logging bar, with Apple's system tab bar behind the `useSystemTabBar` switch;
  - dark only;
  - Lock Screen and Live Activity chart as **three pair lines**, with green minute bars as the fallback;
  - raw counts only;
  - **Try the demo instead** on the pairing screen;
  - **Alert when updates stop: after N min** in Settings, wired into the overdue alert and the overdue phase;
  - **Radio diagnostics** card stubbed until the firmware has `wifi_status`;
  - Runs header summary ("6 runs · 79 h of physics");
  - FPGA card shows a bitstream name only if the detector reports one.
- Made the host tests self-contained (C encoder → Swift decoder, plus the pure-Swift core) and ran them on Linux with the swift.org toolchain.
- The code has **not yet been compiled in Xcode**. See the README for known risks.
